# Живое расписание

Недельная сетка занятий с drag&drop, изменением длительности, категориями,
цветами имён и импортом из Google Таблиц. Одна общая доска: все, у кого
открыта ссылка, видят изменения сразу.

Раньше синхронизация работала только внутри claude.ai (Claude Artifacts).
Теперь это статический сайт на **GitHub Pages** + общее состояние в
**Firebase Realtime Database**.

## Структура

| Файл | Назначение |
|------|------------|
| `index.html` | Разметка и стили. Ничего не меняем при обычной работе. |
| `app.js` | Вся логика: рендер, drag&drop, resize, импорт, синхронизация с Firebase. |
| `firebase-config.js` | Конфиг вашего проекта Firebase. **Только сюда вставляются ключи.** |
| `original-schedule.html` | Исходная одностраничная версия для Claude Artifacts (не используется, оставлена для истории). |

Ни сборки, ни npm, ни фреймворков. Firebase подключается модульным SDK 10
напрямую с CDN `gstatic.com` через `<script type="module">`.

---

## 1. Создать проект Firebase

1. Откройте <https://console.firebase.google.com> и войдите под своим Google-аккаунтом.
2. **Add project** → задайте имя (например `live-schedule`) → можно отключить Google Analytics → **Create project**.

## 2. Включить Realtime Database

1. В левом меню: **Build → Realtime Database** → **Create Database**.
2. Выберите регион (например `europe-west1`).
3. Правила безопасности — выберите **Start in test mode** → **Enable**.

   ⚠️ **Тестовый режим означает, что база полностью открыта на чтение и запись
   всем в интернете** (кто угодно, зная `databaseURL`, может читать и стирать
   данные). Для общего некритичного расписания это приемлемо на старте, как и
   было задумано (доступ по ссылке без логина). Если данные станут
   чувствительными — сузьте правила (см. раздел «Правила» ниже).

   Тестовый режим также автоматически истекает через 30 дней — тогда правила
   нужно будет продлить или заменить вручную.

## 3. Получить конфиг и вставить его

1. **Project settings** (шестерёнка вверху слева) → вкладка **General**.
2. Прокрутите до **Your apps** → нажмите значок **`</>`** (Web).
3. Задайте псевдоним приложения (например `web`), **App nickname** →
   **Register app**. Firebase Hosting подключать не нужно.
4. Firebase покажет объект `firebaseConfig`. Скопируйте значения в
   `firebase-config.js` этого репозитория, заменив плейсхолдеры:

   ```js
   export const firebaseConfig = {
     apiKey: "AIza...",
     authDomain: "live-schedule-xxxx.firebaseapp.com",
     databaseURL: "https://live-schedule-xxxx-default-rtdb.europe-west1.firebasedatabase.app",
     projectId: "live-schedule-xxxx",
     storageBucket: "live-schedule-xxxx.appspot.com",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcdef123456"
   };
   ```

   **`databaseURL` обязателен.** Если его нет в показанном объекте — возьмите
   его со страницы **Realtime Database** (адрес вида
   `https://<project>-default-rtdb.<region>.firebasedatabase.app`).

   > `apiKey` для Firebase Web **не является секретом** — он всегда виден в
   > коде клиента. Доступ ограничивается правилами базы, а не ключом.

5. Закоммитьте и запушьте изменение `firebase-config.js`.

При первом открытии страницы, если узел `/schedule` в базе пустой,
приложение автоматически запишет туда стартовое расписание (то же, что было
зашито в исходном HTML).

---

## 4. Опубликовать через GitHub Pages

1. Запушьте проект в репозиторий на GitHub (ветка `main`), файлы
   `index.html`, `app.js`, `firebase-config.js` — в корне репозитория.
2. На GitHub: **Settings → Pages**.
3. **Build and deployment → Source:** `Deploy from a branch`.
4. **Branch:** `main`, папка `/ (root)` → **Save**.
5. Через минуту-две обновите страницу — вверху появится адрес сайта.

Финальный URL:

```
https://<username>.github.io/<repo>/
```

Этой ссылкой можно делиться — любой, кто её открыл, может редактировать
расписание, и все изменения видят друг у друга в реальном времени.

## Индикатор синхронизации

Пилюля в правом верхнем углу отражает реальное состояние соединения с
Firebase:

| Текст | Значение |
|-------|----------|
| Синхронизировано | Соединение с базой активно, локальных несохранённых правок нет. |
| Сохранение… | Есть правка, которая ещё пишется в базу (debounce 500 мс). |
| Нет соединения | `.info/connected` = false: нет сети или база недоступна. Правки применяются локально и уйдут в базу при восстановлении связи. |

---

## Правила безопасности (когда захотите сузить)

Полностью открытая база (`".read": true, ".write": true`) — самый простой
вариант, но любой может стереть данные. Промежуточные варианты:

- **Только на чтение для всех, запись — по секрету в URL:** не поддерживается
  напрямую, нужен минимальный бэкенд или Firebase Auth.
- **Аноним-аутентификация (Firebase Anonymous Auth):** включить в
  **Authentication → Sign-in method → Anonymous**, в `app.js` добавить
  `signInAnonymously()`, а правила сделать `".read": "auth != null",
  ".write": "auth != null"`. Это не мешает «доступу по ссылке», но отсекает
  ботов без токена.
- **Ограничить размер/форму данных** валидаторами `.validate` в правилах.

Пока расписание некритично — можно оставить тестовый режим и просто продлевать
срок правил в консоли.
