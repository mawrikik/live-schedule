# Живое расписание

Недельная сетка занятий с drag&drop, изменением длительности, категориями,
цветами имён и импортом из Google Таблиц. Одна общая доска: все, у кого
открыта ссылка, видят изменения сразу.

Раньше синхронизация работала только внутри claude.ai (Claude Artifacts).
Теперь это статический сайт на **GitHub Pages** + общее состояние в
**Firebase Realtime Database**.

## Структура

| Файл | Назначение |
|------|------------|
| `index.html` | Разметка и стили. Ничего не меняем при обычной работе. |
| `app.js` | Вся логика: рендер, drag&drop, resize, импорт, синхронизация с Firebase, вход по email/паролю. |
| `firebase-config.js` | Конфиг вашего проекта Firebase. **Только сюда вставляются ключи.** |
| `original-schedule.html` | Исходная одностраничная версия для Claude Artifacts (не используется, оставлена для истории). |

Ни сборки, ни npm, ни фреймворков. Firebase (App, Realtime Database, Auth)
подключается модульным SDK 10 напрямую с CDN `gstatic.com` через
`<script type="module">`.

**Доступ:** страницу видят все, у кого есть ссылка. Редактировать
(drag&drop, resize, формы, импорт, очистка) может только вошедший через
кнопку **«Войти»** владелец — email/пароль из Firebase Authentication.
Сессия сохраняется между визитами (не нужно логиниться каждый раз).

---

## 1. Создать проект Firebase

1. Откройте <https://console.firebase.google.com> и войдите под своим Google-аккаунтом.
2. **Add project** → задайте имя (например `live-schedule`) → можно отключить Google Analytics → **Create project**.

## 2. Включить Realtime Database

1. В левом меню: **Build → Realtime Database** → **Create Database**.
2. Выберите регион (например `europe-west1`).
3. Правила безопасности — можно выбрать **Start in test mode** для первого
   запуска, но сразу после настройки входа (раздел 4) замените правила на
   вариант «чтение всем, запись только владельцу» из раздела
   **«Правила безопасности»** ниже.

   ⚠️ Тестовый режим = база полностью открыта на запись всем в интернете и
   истекает через 30 дней. Не оставляйте его.

## 3. Получить конфиг и вставить его

1. **Project settings** (шестерёнка вверху слева) → вкладка **General**.
2. Прокрутите до **Your apps** → нажмите значок **`</>`** (Web).
3. Задайте псевдоним приложения (например `web`), **App nickname** →
   **Register app**. Firebase Hosting подключать не нужно.
4. Firebase покажет объект `firebaseConfig`. Скопируйте значения в
   `firebase-config.js` этого репозитория, заменив плейсхолдеры:

   ```js
   export const firebaseConfig = {
     apiKey: "AIza...",
     authDomain: "live-schedule-xxxx.firebaseapp.com",
     databaseURL: "https://live-schedule-xxxx-default-rtdb.europe-west1.firebasedatabase.app",
     projectId: "live-schedule-xxxx",
     storageBucket: "live-schedule-xxxx.appspot.com",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcdef123456"
   };
   ```

   **`databaseURL` обязателен.** Если его нет в показанном объекте — возьмите
   его со страницы **Realtime Database** (адрес вида
   `https://<project>-default-rtdb.<region>.firebasedatabase.app`).

   > `apiKey` для Firebase Web **не является секретом** — он всегда виден в
   > коде клиента. Доступ ограничивается правилами базы, а не ключом.

5. Закоммитьте и запушьте изменение `firebase-config.js`.

При первом открытии страницы **вошедшим владельцем**, если узел `/schedule`
в базе пустой, приложение автоматически запишет туда стартовое расписание
(то же, что было зашито в исходном HTML). Незалогиненный зритель при пустой
базе просто видит встроенное расписание по умолчанию, ничего не записывая.

---

## 4. Вход по email/паролю (Firebase Authentication)

1. В консоли: **Build → Authentication** → **Get started**.
2. Вкладка **Sign-in method** → в списке провайдеров выберите
   **Email/Password** → включите верхний тумблер **Enable** (ссылку для входа
   по email, «Email link», включать не нужно) → **Save**.
3. Вкладка **Users** → **Add user** → введите свой email и пароль →
   **Add user**.
4. В таблице пользователей появится строка с колонкой **User UID**
   (например `a1b2c3d4e5f6...`). Нажмите на неё, чтобы скопировать —
   этот UID нужен для правил Realtime Database (раздел
   **«Правила безопасности»**).

На сайте: кнопка **«Войти»** рядом со статус-пилюлей открывает модалку с
полями email/пароль. После входа появляется кнопка **«Выйти»**, интерфейс
разблокируется. Сессия хранится браузером (Firebase, persistence по
умолчанию) и восстанавливается при следующем заходе через
`onAuthStateChanged` — повторно логиниться не нужно.

Неверный email или пароль показываются во всплывающем диалоге приложения.

---

## 5. Опубликовать через GitHub Pages

1. Запушьте проект в репозиторий на GitHub (ветка `main`), файлы
   `index.html`, `app.js`, `firebase-config.js` — в корне репозитория.
2. На GitHub: **Settings → Pages**.
3. **Build and deployment → Source:** `Deploy from a branch`.
4. **Branch:** `main`, папка `/ (root)` → **Save**.
5. Через минуту-две обновите страницу — вверху появится адрес сайта.

Финальный URL:

```
https://<username>.github.io/<repo>/
```

Этой ссылкой можно делиться. Смотреть расписание может любой; редактировать —
только вы, после входа через кнопку «Войти». Изменения появляются у всех
зрителей в реальном времени.

---

## Отмена действий (Ctrl+Z)

После входа доступна отмена последнего изменения по **Ctrl+Z** (на macOS —
**Cmd+Z**); нажатие несколько раз отменяет несколько последних действий.
Повтор отменённого — **Ctrl+Shift+Z** или **Ctrl+Y**.

Отслеживаются все правки расписания: добавление/удаление/перемещение занятий,
resize, изменение категорий, импорт, «Очистить всё». Новое изменение
очищает стопку повтора. История живёт в памяти вкладки — сбрасывается при
перезагрузке страницы и при выходе из аккаунта. Внутри текстовых полей и
при открытом диалоге Ctrl+Z работает как обычно (правит текст, а не
расписание).

## Индикатор синхронизации

Пилюля в правом верхнем углу:

| Текст | Значение |
|-------|----------|
| Только просмотр | Вы не вошли. Расписание видно, но редактирование заблокировано. |
| Синхронизировано | Вы вошли, соединение с базой активно, несохранённых правок нет. |
| Сохранение… | Есть правка, которая ещё пишется в базу (debounce 500 мс). |
| Нет соединения | `.info/connected` = false: нет сети или база недоступна. Правки применяются локально и уйдут в базу при восстановлении связи. |

---

## Правила безопасности

Рекомендуемые правила: **читают все, пишет только владелец.** Замените в
консоли (**Realtime Database → Rules**) `YOUR_UID` на свой User UID из
Firebase Authentication (раздел 4, вкладка Users):

```json
{
  "rules": {
    "schedule": {
      ".read": true,
      ".write": "auth != null && auth.uid === 'YOUR_UID'"
    },
    ".read": false,
    ".write": false
  }
}
```

Приложение никогда не пытается писать в базу до входа, поэтому лишних ошибок
`permission-denied` в консоли браузера не будет.

Хотите закрыть и чтение — поставьте `".read": "auth != null"`, но тогда
незалогиненные зрители не увидят расписание (это ломает сценарий «доступ по
ссылке»). Форму данных можно дополнительно проверять валидаторами
`.validate`.
